For the IT department

Do not trust us. Check it.

FrostCopy promises that the documents never leave the computer. Here are the commands that show it, what they should answer, and what each check actually proves.

In short

  • No way out. The program has no TLS, cannot look up a name on the network and does not listen on any port.
  • Everything is in the package. Nothing is downloaded after installation. No updater, no usage statistics, no error reports.
  • You can block it. Block all outbound traffic for FrostCopy. The program works just as well.
  • You can manage it. One file decides what the users may choose themselves.

Which system are you checking?

1Is this our file?

shasum -a 256 ~/Downloads/FrostCopy*.dmg
Get-FileHash "$HOME\Downloads\FrostCopy*.exe"

Expected: the long string of digits and letters is the same as the checksum listed here for the file.

2Is it signed by us, and untouched?

codesign -dv --verbose=4 /Applications/FrostCopy.app 2>&1 | grep -E "Format|TeamIdentifier|flags|Notarization"

Expected: Format=app bundle with Mach-O universal (x86_64 arm64), flags=0x10000(runtime), Notarization Ticket=stapled and TeamIdentifier=N5BKVM258S. 

spctl -a -vv /Applications/FrostCopy.app

Expected: accepted and source=Notarized Developer ID.

The package has two more executable files: the helper that looks after the key, and the PDF library. The helper is there once more, inside Contents/Helpers/FrostCopy.app. Check them too:

codesign -dv /Applications/FrostCopy.app/Contents/MacOS/klart-hvelv 2>&1 | grep TeamIdentifier
codesign -dv /Applications/FrostCopy.app/Contents/Resources/bundled/engine/pdfium/libpdfium.dylib 2>&1 | grep TeamIdentifier

Expected: the same TeamIdentifier=N5BKVM258S on both.

The Windows edition is signed by ESBJUG CONSULT, with a timestamp.

Get-AuthenticodeSignature "$HOME\Downloads\FrostCopy*.exe" | Format-List Status, SignerCertificate

Expected: Valid, and our name, ESBJUG CONSULT, in SignerCertificate.

Proves: that the code is ours and has not been changed afterwards. This is the test against a rebuilt copy. A copy with a network connection added is a different program, and the signature is what reveals it.

3What is it allowed to do?

codesign -d --entitlements - --xml /Applications/FrostCopy.app 2>/dev/null | plutil -p -

Expected: five lines, all false: automation.apple-events, cs.allow-dyld-environment-variables, cs.allow-jit, cs.allow-unsigned-executable-memory and cs.disable-library-validation. No iCloud entitlements, and neither network.client nor network.server.

But read this: FrostCopy does not run in the App Sandbox. So the missing network entitlements are only a piece of information. macOS does not enforce them without the sandbox, and a program with Hardened Runtime can in principle open a connection anyway. We would rather say so than have you find it yourselves. What actually settles the matter is steps 4 and 5, and the rule you set yourselves.

Proves: that the program cannot control other programs, cannot load foreign code, and has no access to iCloud. About the network it proves nothing on its own.

Windows has no corresponding entitlements for ordinary desktop programs. A program installed with an .exe does not ask for permission to use the network. It has it. That is why there is no command here.

Proves: nothing on Windows. The block is the firewall rule further down, and the proof that the program is silent is step 4.

4Does it talk to anyone?

Start FrostCopy, open a folder and let it read. Run the command while it is working.

pgrep -lx frostcopy; lsof +c 0 -nP -a -i -c frostcopy -c com.apple.WebKit.Networking

Expected: one line with the process number and frostcopy, and nothing after it. FrostCopy does not have a single TCP or UDP socket.

The FrostCopy window is drawn by WebKit, which comes with macOS. WebKit starts its own helper processes, and one of them is called com.apple.WebKit.Networking. It is included in the command, because it is the one that would fetch something if the window tried. It should be empty too.

If rows appear anyway, you probably have Safari, Mail or another program with WebKit open. They share the name of the helper process. Close them and run it again, or look at the process numbers: FrostCopy's helpers have the numbers right after FrostCopy.

Mind the -a. Without it, lsof reads the options as “or”, and you get the whole computer's traffic in the list. LuLu or Little Snitch gives the same answer, if you would rather see it that way. 

Get-Process frostcopy, tesseract -ErrorAction SilentlyContinue |
ForEach-Object {
  "$($_.ProcessName) is running (process $($_.Id))"
  Get-NetTCPConnection -OwningProcess $_.Id -ErrorAction SilentlyContinue
  Get-NetUDPEndpoint -OwningProcess $_.Id -ErrorAction SilentlyContinue
}

Expected: only the lines that say frostcopy is running, and tesseract while FrostCopy reads an image. No tables of addresses and ports.

The FrostCopy window is drawn by WebView2, which is Microsoft's and comes with Windows. It runs as separate processes, msedgewebview2.exe. The content of the window may not fetch anything: the rules in step 5 block that. But WebView2 itself can talk to Microsoft, for example about its own updates. That is Microsoft's traffic, and it contains nothing from FrostCopy or the documents. If you want it completely silent, block both in the firewall.

Resource Monitor (resmon), the Network tab, gives the same answer if you would rather see it that way.

Proves: that the program, as it runs on your computers, has no way out. This is the check we trust most ourselves.

5What is it made of?

The whole package on Mac is 379 MB installed. This is everything in it:

MacOS/frostcopy
The program. 111 MB, for both Intel and Apple processors. The shell is Rust (Tauri 2), the window is TypeScript.
MacOS/klart-hvelv
A small helper (0.2 MB) that wraps and unwraps the key with the keychain and the Secure Enclave.
setning/distilbert-english.onnx
The sentence model: based on distilbert-base-cased and fine-tuned for FrostCopy, 249 MB. It runs on the processor, inside the program itself. It is not a separate process.
setning/vocab.txt
The model's word list, 0.2 MB.
pdfium/libpdfium.dylib
PDFium, the library that reads and draws PDFs. 15 MB.
find /Applications/FrostCopy.app/Contents -type f -size +100k -exec ls -lh {} \;

Expected: the five files above, the key helper once more under Contents/Helpers, the licence file THIRD-PARTY-CODE.txt and the app icons. No llama-server, no .gguf, no other models.

The program has no TLS and no HTTP client that can reach a host. It cannot listen on a port, and it cannot look up a name on the network. You can see that in the file itself: 

otool -L /Applications/FrostCopy.app/Contents/MacOS/frostcopy | grep -iE 'curl|CFNetwork|Network\.framework|ssl'
nm -u /Applications/FrostCopy.app/Contents/MacOS/frostcopy | grep -E '_(bind|listen|accept|getaddrinfo)$'

Expected: no lines from either of them.

What you will find, and what it is: the file has socket and connect, and the word llama-server is in it. These are remnants of a local language model that was taken out on 4 November 2026. The code that talked to it over a file socket is still there, but the package has no model to start. At startup FrostCopy looks for an old model process that may have been left running, with pgrep. A monitoring tool will notice that.

The file is also linked against CloudKit and CoreData. That comes from the window library, not from us. FrostCopy uses neither of them, and has no iCloud entitlements (step 3).

If you have the source code, these are the places to look:

src-tauri/Cargo.toml
No reqwest, hyper, rustls, native-tls or openssl. tokio is built without net. Some of the names are in Cargo.lock anyway, because a library has them for mobile. They are never built in. That is why cargo tree is what counts, and a search in the lock file is not.
tauri.conf.json
CSP for the window: default-src 'self' and connect-src ipc: http://ipc.localhost. The window may only talk to the program it is in. No frames, no embedded objects, no forms out. In addition, the program stops any navigation away from itself.
capabilities/default.json
The window is denied opening addresses and paths: opener:deny-open-url, deny-open-path and deny-reveal-item-in-dir. No http plugin, no updater.
scripts/sjekk-nett.sh
Runs before every build. It reads the compiled dependency graph, looks for addresses and for std::net in the Rust code, and stops the build if any of this comes back.
cd src-tauri && cargo tree -e normal | grep -E 'reqwest|hyper|rustls|native-tls|openssl'

Expected: no hits.

In one place FrostCopy opens a web address: when the user presses “Buy a licence”, the program asks the system to open https://esbjugconsult.com/klart/us/buy?hva=…&maskin=… in the user's own browser. FrostCopy does not connect there itself. The machine code in the address is a SHA-256 of the computer's ID, and says nothing about the user or the documents.

The libraries that read the documents

These receive files you did not make yourselves, so you will want to know about them:

PDFium 158, pdf.js 4.10.38 and pdf-lib 1.17.1. pdf.js runs without eval.

JSZip 3.10.1 and docx-preview 0.4.1.

SheetJS (xlsx) 0.18.5.

Proves: that there is no code in the program that can send anything. If you have the source, you can build it yourselves and compare.

Block it yourself

Do not trust us. Block outbound traffic for FrostCopy in the firewall or with MDM. The program works just as well. That is the whole point of building it this way.

The firewall that comes with macOS only stops incoming traffic. Put the path in a rule in your MDM's network filter, or in LuLu or Little Snitch:

/Applications/FrostCopy.app/Contents/MacOS/frostcopy

The installer (.exe) tries to add the rule itself. This is how you see whether it is there:

Get-NetFirewallRule -DisplayName "FrostCopy*" | Get-NetFirewallApplicationFilter

Expected: a rule called “FrostCopy - block outbound”, with the path to frostcopy.exe.

If it is missing, add it like this, in PowerShell as administrator:

New-NetFirewallRule -DisplayName "FrostCopy - block outbound" `
  -Direction Outbound -Action Block -Profile Any `
  -Program (Get-Process frostcopy).Path

Run it while FrostCopy is open, and the command finds the path itself. Also include tesseract.exe, which is in the folder bundled under FrostCopy. It is a separate executable file. Via Intune: make the same rules in a firewall policy under Endpoint security.

When the rule is yours, you do not need to take our word for any of the above.

What is on the disk

FrostCopy stores everything of its own in one folder per user. On Mac it is ~/Library/Application Support/uk.frostcopy.app/, on Windows %APPDATA%\uk.frostcopy.app\.

prosjekter/
What the user has decided in each folder, and the text FrostCopy has read from the files. The latter is personal information. Everything is encrypted with AES-256-GCM, and the folders have names that cannot be read back to the path. A project that is not used is forgotten after 30 days.
pseudonym/
The key (nokkel.nokkelring on Mac, nokkel.dpapi on Windows), earlier keys that have been set aside, and the number book. The number book links codes to numbers and has no names.
secure-enclave.nokkel
On Macs with a Secure Enclave: a reference to a key in the chip. It is useless on another computer.
ror/
The user's own marks and the texts from the Text tool. Encrypted.
sikkerhetskopier/
Copies of the originals, taken before the scan when the user asks for it. The content of each file is encrypted with AES-256-GCM. The file and folder names are in plain text. The copies are not deleted by themselves. FrostCopy reminds the user about them after 30 days.
revisjon/
The audit log, when it is turned on. One file per month, the last 13 months.
Three small files
aktivering.json (the licence code), innstillinger.json and vindu.json. Not encrypted, and with nothing from the documents.

How the keys are protected

On Mac the key is wrapped with another key that is in the keychain (the service no.klart.pseudonym.uk.frostcopy.app), and with the Secure Enclave where there is one. On Windows, DPAPI for the user is used. That protects against another user and against a disk that goes astray. It does not protect against a program that runs as the same user. That is the limit of both the keychain and DPAPI, and you should know about it.

Backup and search

prosjekter/, sikkerhetskopier/ and revisjon/ are kept out of Spotlight and Time Machine (and Windows Search). ror/ and pseudonym/ are included in Time Machine. They are encrypted, and the key file can only be opened with the keychain on the computer it came from.

What FrostCopy adds to the system

Services in Finder
On Mac, FrostCopy writes four services to ~/Library/Services/ at startup: “Clean with FrostCopy”, “Restore with FrostCopy”, “Clean Text with FrostCopy” and “Restore Text with FrostCopy”. The last two receive selected text from other programs. With "kommandolinje": false in the policy, all four are removed.
Addresses and file types
FrostCopy accepts frostcopy://links, and the file types .frostcopylicense and .frostcopymarks. A link can suggest a licence. The user is always asked, and a key package still needs its code.
Nothing in the background
No service, no startup entry and no process that stays when the window is closed.
What your monitoring will see
FrostCopy starts some short helpers from the system: klart-hvelv (the key), ioreg (the machine code), id and scutil (user and computer name for the list of changes), tmutil (keeping folders out of Time Machine), open (showing the copy folder) and osascript (notifications).

Remove everything

Delete the program, and then this:

rm -rf ~/Library/Application\ Support/uk.frostcopy.app ~/Library/WebKit/uk.frostcopy.app ~/Library/Caches/uk.frostcopy.app
rm -f ~/Library/Preferences/uk.frostcopy.app.plist
rm -rf ~/Library/Services/*FrostCopy.workflow
security delete-generic-password -s no.klart.pseudonym.uk.frostcopy.app

Uninstall the program, and then delete %APPDATA%\uk.frostcopy.app\, %LOCALAPPDATA%\uk.frostcopy.app\ and %ProgramData%\FrostCopy\.

Keep the key safe first. If the data folder is deleted before the key is written down or saved as a key file, no copy with codes can ever be restored.

Manage FrostCopy centrally

One file decides what the user otherwise chooses. Deploy it with MDM, Intune, group policy or a script. Both locations require an administrator to write, so the user cannot undo what you have locked. The file name and the field names are Norwegian in this version.

Mac
/Library/Application Support/FrostCopy/retningslinjer.json
Windows
%ProgramData%\FrostCopy\retningslinjer.json
{
  "versjon": 1,
  "virksomhet": "Acme Ltd",
  "alltidSkjult": ["navn", "fnr", "helse"],
  "kodeform": "kort",
  "ansikterAlltid": true,
  "utenSkanning": false,
  "glemEtterDager": 30,
  "revisjonslogg": true,
  "nokkelEksport": false
}
versjon
Required. Only 1 exists.
virksomhet
The name shown next to what is locked: “Set by Acme Ltd”.
alltidSkjult
The groups that are always hidden. They cannot be turned off, and nothing in them can be set to keep. The groups are called navn, fnr, kontakt, helse, setninger, skilt, penger, hemmelig, sted, dato, org and sak.
standardGrupper
The groups that are on when a folder is opened for the first time. Without it: FrostCopy's own.
kodeform
lapp, kort or full. Without it: the user chooses.
ansikterAlltid
Faces are always pixelated, and none can be set to keep.
utenSkanning
false requires that FrostCopy always reads the files. By default the user can also mark everything by hand.
prosjekter
false: FrostCopy remembers nothing about the folders between sessions.
glemEtterDager
How long an unused project is kept, 1 to 365. The default is 30.
kommandolinje
false turns off the command line and the watched folder.
revisjonslogg
Turns on the log. revisjonsmappe also gives a copy on a shared drive.
rapportJson
Writes rapport.json next to rapport.txt in every copy folder.
nokkelEksport
false: nobody can take the key out as words or as a file. New computers are enrolled by the key manager.

The licence can sit next to it, in licence.frostcopy. Then no user needs to paste anything in. If the user has a valid licence of their own, it takes precedence.

If the file cannot be read, FrostCopy does not start. A typo, an unknown field or a value outside what is allowed must not lead to FrostCopy cleaning with less than you decided. The error message says which field it concerns.

The key in an organisation

The codes in the copies can only be turned back into names with the key. In an organisation everyone should have the same one. Otherwise the same person gets different codes with different colleagues.

Key manager
Makes the organisation's key, shares it and enrolls colleagues.
Member
Uses the key. The program does not let a member take it out. That is a rule in the program and it is not cryptography: the computer has the whole key.
Key package
The key encrypted with a key code of twelve characters (Argon2id and AES-256-GCM). The package and the code are sent separately. The code can be used several times, so treat it like the key.
Enrolment without a network
The colleague's computer makes a request. The key manager answers with an enrolment that only that computer can open (X25519). A check code of six digits is read aloud, so both know they are talking to the right computer.
Recovery
24 words on paper, or a key file locked with a passphrase (Argon2id and AES-256-GCM).

Silent rollout has a price. You can put the key package next to retningslinjer.json and write the key code in the file (nokkelkode). Then FrostCopy starts using the key without the user doing anything. But then the key is no safer than the folder: whoever can read both files has the organisation's key.

Audit log

The log says what FrostCopy has done, when and by whom. It has nothing from the documents: no file names, no paths and no values. It is off until you turn it on with "revisjonslogg": true. 

{"format":1,"tid":"2026-11-05T11:50:25.332Z","hendelse":"rens","via":"kommandolinjen",
 "kilde":"DXmRKTRw4ZJMiUixyVeUYA","filer":18,"skrevet":14,"ikkeLevert":4,"steder":193,
 "skjult":{"person":140,"fnr":19,"health":25},"kodeform":"kort","grupper":["helse","navn","fnr"],
 "ansikter":true,"gjennomgått":false,"bruker":"olivia","maskin":"OLIVIA-MAC","klart":"0.1.0"}
hendelse
rens, prøve, skann, glem, tilbake or logg (the list of changes has been exported).
via
appen, kommandolinjen or vaktmappen.
kilde
A fingerprint of the folder, computed with a key on the computer. The same case has the same value in every line on that computer, but the path cannot be read out of it. Another computer gives a different value for the same folder.
bruker, maskin, tid
Set by the program itself, never by the window.
Where
revisjon/YYYY-MM.jsonl in the data folder. With revisjonsmappe also <maskin>-<bruker>.jsonl on a shared drive. FrostCopy does not create that folder. If the drive is not connected, the local log says so.

The log is an ordinary text file. The user can change it. If you need a log that cannot be touched, point revisjonsmappe to a location where the user can only append.

Command line and watched folder

The same program, with no window. The channel in is the command line. The channel out is stdout, stderr and the files you point to. Nothing opens a port. 

FROSTCOPY=/Applications/FrostCopy.app/Contents/MacOS/frostcopy

$FROSTCOPY scan ~/Cases/2026-114                          # read ahead
$FROSTCOPY clean ~/Cases/2026-114 --out ~/For-AI          # make cleaned copies
$FROSTCOPY clean ~/Cases/2026-114 --out ~/For-AI --changed-only
$FROSTCOPY watch ~/Inbox --out ~/For-AI                   # watched folder
$FROSTCOPY restore ~/For-AI/2026-114-clean                # restore with the key
$FROSTCOPY forget ~/Cases/2026-114                        # forget everything about the case
--codes
lapp, kort, full or svart.
--groups
What is replaced, such as navn,fnr,helse.
--dry-run
Does everything, including the check of each copy, but writes nothing.
--no-project
Remembers nothing, and does not use what was decided in the window.
The reply
One JSON line on stdout, with format: 1. Progress goes to stderr, as numbers only.
Exit code
0: everything was delivered. 2: something was held back, because a copy did not pass the check or a file could not be read. 1: error.

Cryptography

The key
32 random bytes from the operating system. Subkeys with HKDF-SHA256.
The codes
Who it is: HMAC-SHA256. The text that was there: AES-SIV (RFC 5297), which is deterministic and authenticated.
The key on disk
Mac: the keychain and the Secure Enclave. Windows: DPAPI.
Key file
Argon2id (64 MiB, 3 rounds) and AES-256-GCM.
The 24 words
A 256-bit key and an 8-bit checksum, 11 bits per word, from a list of 2,048 Norwegian words.
Enrolment
X25519.
Projects, your marks and texts
AES-256-GCM, with keys from HKDF-SHA256. The file names are HMAC fingerprints.
Backups, and the pixels under the boxes in a copy
AES-256-GCM.
The licence code
Ed25519. The signature is checked on the computer.

All of it is well-known algorithms from open libraries (RustCrypto and dalek). We have not made anything of our own.

System requirements

Mac
macOS 13 or later. Intel and Apple processors in the same package.
Windows
Windows 10 or 11, 64-bit with Intel or AMD. Installed for all users, with an .exe.
Linux
A .deb package for amd64 (Intel or AMD) and one for arm64. It depends on tesseract-ocr and xdg-utils, which the package manager installs.
Memory
FrostCopy uses the most memory while the sentence model is loaded. We recommend 8 GB in the computer.
Disk
379 MB installed on Mac. In addition come backups and what FrostCopy remembers about the folders.
Graphics card
Not needed. Everything runs on the processor.
Network
Not needed, neither for installation, activation nor use.

The first time FrostCopy reads images on a Mac, macOS can take a few minutes to prepare its own text recognition. It happens once.

Black redaction as PDF, the services in Finder and licence links are only on Mac for now.

An update is a new installer you fetch yourselves, when you want. FrostCopy does not look for new versions.

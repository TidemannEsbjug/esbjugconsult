Non. Clair & Klaar ne se connecte jamais à Internet et fonctionne aussi bien hors ligne.

Ce que contient le paquet

Clair & Klaar est un logiciel de bureau ordinaire. L’enveloppe est écrite en Rust (Tauri), la fenêtre est une vue web avec une interface en TypeScript. Tout le nécessaire se trouve dans le fichier d’installation. Rien n’est téléchargé ensuite.

Moteur de règles
TypeScript. Fonctionne dans le logiciel, sans serveur.
Modèle de phrases
Fondé sur distilbert-base-en-fr-nl-ru-ar-cased de Geotrend (Apache 2.0), ajusté pour Clair & Klaar et converti au format ONNX, environ 320 Mo. Fonctionne sur le processeur, sans carte graphique.
Texte dans les images
Apple Vision sur le Mac, Tesseract (néerlandais, français et allemand) sous Windows et Linux.
Visages
Apple Vision, sur le Mac.
PDF
PDFium dessine les pages et lit la couche de texte.
Pas de grand modèle de langue
Clair & Klaar n’a ni LLM ni chatbot. La compilation s’arrête si l’un d’eux se trouve dans le paquet.

Du fichier à l’élément trouvé

Chaque fichier est découpé en morceaux de texte qui savent où ils se trouvent : paragraphe, cellule, zone de texte, en-tête ou endroit d’une page PDF. Puis trois lecteurs parcourent le texte.

Les règles
Le numéro de registre national doit avoir un chiffre de contrôle correct (97 moins le reste modulo 97, avec un « 2 » devant pour les personnes nées à partir de 2000), tout comme le numéro BIS, le numéro d’entreprise (BCE), la carte eID et l’IBAN (modulo 97). Les noms sont trouvés grâce aux listes de Statbel et de Wikidata et à leur position, par exemple après « Nom : » ou dans une signature.
Mots sensibles
Une liste de mots pour la santé, le syndicat, la religion et les condamnations, avec leurs formes fléchies. « en arrêt maladie », « arrêt de travail » et « placée en arrêt maladie » relèvent du même résultat.
Le lecteur de phrases
Le modèle de phrases donne à chaque phrase portant sur une personne une note indiquant à quel point elle est privée. Avec le lecteur de mots, cela décide si la phrase devient une « Information personnelle ».
Les coordonnées de l’organisation
L’adresse de l’en-tête, le standard, le numéro d’entreprise et le compte professionnel sont reconnus et restent visibles. Les adresses e-mail sont malgré tout masquées.

Pour finir, les résultats sont rassemblés dans le registre du dossier. « Marie », « Marie Dupont » et « MARIE DUPONT » deviennent une seule personne, dans tous les fichiers. Ce dont Clair & Klaar n’est pas sûr arrive, avec la raison, dans la file « À trancher » : le nom est en début de phrase, deux personnes portent le même nom, ou le mot a été ajouté après coup.

Les codes

Un code a deux parties. L’une dit de qui il s’agit. L’autre est le texte d’origine, chiffré.

[PERSON_VBTF60YD0E-J94DW5ZFTYA2GWTWAXFKK0XYBF1KTY19BED6E5TJ832VZ00]

Le code de la personne
HMAC-SHA256 du type et de la valeur, réduit à dix caractères. Identique pour toutes les graphies d’un même nom, pour qu’un outil d’IA reconnaisse qu’il s’agit de la même personne.
La partie chiffrée
AES-SIV (RFC 5297) du texte exactement tel qu’il figurait. Le même texte donne toujours le même code. Un code modifié ou créé avec une autre clé est rejeté. Clair & Klaar ne remet jamais une information erronée.
Le numéro court
Le numéro de [Nom 4829133] est calculé à partir de la clé et de la valeur. Il est donc le même sur tous les ordinateurs qui ont la même clé, sans qu’ils communiquent entre eux.
La liste des codes
Dans la forme de copie habituelle, le numéro court figure dans le texte et les codes complets dans une liste à la fin. Avec la clé, cette liste est tout ce qu’il faut pour restaurer la copie.

La clé

Ce qu’elle est
32 octets aléatoires, créés sur l’ordinateur au premier démarrage de Clair & Klaar. Les sous-clés des codes, des numéros et des images sont dérivées avec HKDF-SHA256.
Où elle se trouve
Protégée par le système d’exploitation : trousseau et Secure Enclave du Mac. La clé est gardée dans la partie Rust du logiciel. La fenêtre ne la reçoit que si vous voulez voir les 24 mots.
24 mots
La clé peut s’écrire sous forme de 24 mots norvégiens tirés d’une liste de 2048. Les mots ne contiennent que les lettres a à z, et aucun ne ressemble à un autre. Les quatre premières lettres suffisent à reconnaître un mot.
Fichier de clé
La clé, chiffrée avec une phrase secrète d’au moins douze caractères (Argon2id et AES-256-GCM).
ID de clé
Un court identifiant comme WJ0R-Q3R5. Il indique avec quelle clé une copie a été créée, mais ce n’est pas la clé elle-même.
Plusieurs clés
Si vous changez de clé, l’ancienne est mise de côté. Pour restaurer, Clair & Klaar essaie d’abord la clé actuelle, puis les précédentes.

Comment la copie est écrite

Word, Excel, PowerPoint
Le fichier est un ZIP contenant du XML. Clair & Klaar remplace les valeurs sur place, même quand Word a découpé un nom en plusieurs morceaux. Puis le fichier est nettoyé : commentaires, macros, fichiers incorporés, vignette et informations cachées dans les images sont retirés.
PDF
Chaque page est dessinée comme une image à 200 dpi, à 300 pour les petits caractères. Les codes sont peints par-dessus les informations, et le texte occulté se trouve, invisible, dessous, pour que la copie reste consultable par recherche.
Images
Les cases sont recouvertes et les visages pixelisés.
Ce qui se trouvait dessous
Si la copie doit être restaurable, Clair & Klaar place les pixels d’origine de chaque case, chiffrés, dans la copie (AES-256-GCM). Les logiciels ordinaires les ignorent.
E-mail
La copie devient un .eml épuré. Les en-têtes techniques sur le trajet de l’e-mail sont retirés.
Noms de fichiers
Si un nom figure dans le nom d’un fichier ou d’un dossier, il est remplacé lui aussi.

Le contrôle avant l’enregistrement

Avant d’écrire une copie, Clair & Klaar la lit comme le ferait un autre logiciel : chaque partie du fichier ZIP, chaque attribut XML, chaque objet du PDF et le texte de chaque image. S’il trouve quelque chose qui aurait dû être masqué, ou une partie qu’il ne sait pas lire, le fichier n’est pas créé. Vous voyez alors de quoi il s’agit.
